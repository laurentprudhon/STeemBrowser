Falcon custom ICs decap and Reverse Engineering

Post by ijor » Mon Jun 30, 2025 1:44 am

This thread relates to this project: Atari Falcon custom chips decapsulated and available for reverse engineering
The idea is to elaborate here about all the technical aspects and leave the thread mentioned above for administrative purposes.

Some preliminary data without too much elaboration:

All three ICs are Gate Arrays. Videl is based on an LSI Gate Array. Combel and Sdma on Motorola Gate Arrays. They are all channel less arrays, sometimes called Sea of Gates.

Combel & Sdma use exactly the same Motorola base Gate Array. The die size is then identical, and also very similar to Videl die size, about 60 sq mm.

Videl is based on a more advanced technology. With the same die size seems to have close to about twice the capacity. Sdma seems to utilizes almost the whole Gate Array, certainly much more than Combel. This means that Combel is the chip with the smallest number of gates and transistors.

Because Combel & Sdma use the same base Gate Array, the number of total available I/O pads is identical, 180. But of course, Combel has much more pins. Then many Combel pins are not connected to the die at all. While Sdma is the opposite, with many unbonded pads ( not connected to any pin).

Post by ijor » Tue Jul 01, 2025 7:15 pm

Somebody asked what exactly is a "Sea of Gates".

Traditional Gate Arrays are composed of rows (or columns, depending on the orientation) with the actual transistor cells used to build the gates. Between the rows there are empty rows (or columns) of space, sometimes called "channels". The channels are used for the metal routing interconnect.

See this example from the Happy HART chip taken by @Zippy:
Hart-GateArray-sample1.jpg
You can see the row with the uncommitted transistors at the middle. And the routing channels at the bottom and the top.

Many more modern Gate Arrays are built without channels. They are sometimes called "channelless". A Combel and a Videl sample:
SeaOfGates-sample-2.jpg
SeaOfGates-sample.jpg
You can see that now the whole array is filled with transistors without almost any empty space. Hence the term Sea of Gates. The interconnect now instead of being routed at the empty channels, it is routed, as needed, over unused transistors. The transistors are at the silicon layers and as long as not connected with vias, don't interfere with the metal interconnect.

Obviously, in practice is not possible to use all the available transistors because otherwise you wouldn't be able to connect them. But this pattern is more flexible and allows better and more efficient place and route.

Doesn't that bit just switch the sync signals on and off rather than the pixel clock they are derived from? At least, that's how it works on the ST. The Falcon allows for more granular control and allows HSync and VSync to be disabled independently, via $FF8266). This enables the Falcon to be genlocked in the same way as an Amiga, the HSYNC generated by VIDEL is phase-locked to the incoming video by altering the external clock and then Vsync is switched to external.

That seems to be correct. Wasn't aware that this was documented.

Each buffer has 34 words, each word being 16-bit. The datapath is shared between both buffers. As far as I can see it is not possible to read or write 32-bits simultaneously. But there are separate read and write buses. So it possible to read from one buffer and write to the other at the same time independently.

The depth of the buffers (34) was determined according to CPU utilization
calculations. The two RAM Buffers work in ping pong mode. While one is read
from, the other is loaded. When the one that is read reaches its end a
VREQ signal is issued to the MCU (in the COMBO chip) and reading continues from
the second buffer while the first buffer is being loaded with new data.
