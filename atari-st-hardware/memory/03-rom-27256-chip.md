# Atari ST ROM 27256 Chip

## 1. Overview

The **27256** is a **27xxx series EPROM** (Erasable Programmable Read-Only Memory) chip used in the Atari ST line of computers to store the **TOS** (Tramiel Operating System) firmware. Specifically, it is a **32K x 8-bit (256 Kbit)** UV-erasable ROM in a **28-pin DIP** package.

### Key Specifications

| Parameter | Value |
|---|---|
| Chip family | 27xxx (27256) |
| Type | EPROM (UV-erasable) |
| Capacity | 32K x 8 bits = 256 Kbit = 32 KiB |
| Package | DIP-28 |
| Organization | 32,768 bytes (0x8000) |
| Voltage | +5V Vcc (programming: +12.5V to +21V) |
| Erase method | UV light through quartz window |

### Models and ROM Usage

| Atari ST Model | ROM Chip(s) | ROM Capacity | Notes |
|---|---|---|---|
| Atari ST (MKT540) | U32 (27256) | 32 KiB | Single 27256, TOS 1.00-1.06 |
| Atari ST (MKT520) | U32 (27256) | 32 KiB | Single 27256, TOS 1.06-1.62 |
| Atari STE (MKB520) | U9, U10 (two ROMs) | 64 KiB | Two 27256 chips banked; TOS 2.06-3.06 |
| Atari MegaSTE | U9, U10 (two ROMs) | 128-256 KiB | 27C512 (serial EEPROM); TOS 3.06+ (bootable STE BIOS included) |

The original **Atari ST (520ST/1040ST)** uses a single 27256 for the TOS ROM at address `U32` on the motherboard. The **Atari STE** expanded this to two ROM chips (U9 and U10) for compatibility and additional STE BIOS functionality. The **MegaSTE** replaced discrete ROM with a single 27C512 serial PROM.

### ROM Contents by TOS Version

#### TOS 1.x (original ST)

- **ST-Kernel**: Core OS routines for task management, memory allocation, and interrupts
- **BIOS**: Base Input/Output System (FAT filesystem, disk I/O)
- **MMIo**: Memory-mapped I/O support
- **GEMDOS**: DOS-compatible system call interface
- **ARANYM**: Transputer-compatible execution layer (for ST-DEVS)
- **AES/GEM**: Atari Environment Standard / Graphics Environment Manager in ROM
- **Bootcode**: Bootloader and floppy init

#### TOS 2.x (STE)

- All TOS 1.62 contents
- **STE BIOS extensions**: Hardware initialization for STE features (blitter, DMA ACIA, auto-config)
- **STE chipset init**: Blitter, Shifter, and DMA controller initialization
- **Two ROM layout**: BIOS1 contains original TOS compatibility layer; BIOS2 contains STE extensions
- **STE bootcode**: Extended bootloader for STE floppy controller

#### TOS 3.x (MegaSTE)

- All TOS 3.06 STE contents
- **MegaSTE chipset init**: ST-FMU integration, ST-DMA enhancements
- **Lance Ethernet support**: ROM-based network driver initialization
- **Larger capacity**: Fits in 27C512 (64KiB) vs two 27256s
- **Bootcode**: MegaSTE-specific boot sequence

## 4. Chip Enable / Chip Select Logic

### How the 68000 Accesses ROM

The Motorola 68000 accesses the Atari ST ROM through a combination of **address decoding** and **control signal gating**.

#### Address Decoding for ROM

The 68000's address lines are used to decode the ROM region in the upper 64KB of the 16MB address space:

```
Address lines used for ROM decode:

A15        (MBE# - Master Byte Enable, active low)
A16-A19    (upper address lines)
A20-A23    (Bank select - Mega STE / Mega ST)

ROM is selected when:
  A24-A27 = 1111b (upper memory area)
  + A19 = 1  (select FFFF range)
  + MB# or /BDS/BCL active

Specifically, ROM occupies:
  $FF0000 - $FFFFFF  (ROM region, 64 KiB)

On the original ST (without banked memory), the ROM appears at:
  $FF0000 - $FFFFF   (upper 64KB per byte lane)
  $FF8000 - $FFFFFF   (boot ROM for 68000 reset vector)
```

#### Chip Select Signal Generation

```
┌─────────────────────────────────────────────────────┐
│              ROM Address Decoding                     │
│                                                       │
│   68000 Address Bus A23-A20                          │
│         + A19                                          │
│              │                                          │
│         Decode Logic (74LS138 or custom ASIC)         │
│              │                                          │
│        ROML (ROM lane select - lower)                 │
│        ROML (ROM lane select - upper)                 │
│              │                                          │
│        NAND / gating with MBE#/LBE#                   │
│              │                                          │
│        CE# (Chip Enable for 27256) = active low       │
└─────────────────────────────────────────────────────┘
```

Key signals:
- **ROML (lower lane)**: Active when the 68000 performs a byte/word access where the lower byte is selected
- **ROML (upper lane)**: Active when the upper byte is selected
- **/E (E-cycle)**: 68000 E1/E2 clock phase; drives OE# of ROM during read cycles
- **MBE# (Master Byte Enable)**: Indicates which byte lane is active ($FF, $FE, $FD, $FC)

#### Memory Access Flow

1. 68000 places address `FFxxxxxx` on its address bus
2. Address decoder recognizes upper 4MB region (A24-A27 = 1111)
3. Further decode narrows to `FFF00000-FFFFFF` range
4. ROML/ROMU signals go active based on byte lane
5. 68000 `/E` signal drives ROM OE# during E1/E2 phases
6. 27256 outputs data on D0-D7
7. 68000 reads data during address strobe phase

### ROM and RAM Interleaving (STE)

On the Atari STE, the ROM is mapped such that the BIOS1 occupies the lower half and BIOS2 the upper half of the upper 64KB region:

```
Original ST:              STE:
$FF0000 ┌──────┐$FF4000  $FF0000 ┌────────────┐$FFC000
        │TOS   │               │  BIOS1     │
        │ROM   │               │  (TOS  BIOS │
$FF4000 ├──────┤$FF8000        │ 2 ROMs)    │$FFFF8000
  (RAM) │  ?   │  (ROM area)   ├────────────┤$FFFFF000
        │      │               │  BIOS2     │
        │      │               │  (STE ext) │
$FF8000 └──────┘$FFFFFFF  $FFFFFFF └────────────┘$FFFFFFF
(boot vec)                         (boot vec)
```

### ROM Shadowing

The Atari STE BIOS includes code to **shadow** the ROM into RAM for faster access. This is handled by:

1. **Init_FMU ROM_SHAD function** (STE BIOS): Copies BIOS1+BIOS2 into shadow RAM
2. **STE BIOS shadowing**: BIOS region shadowed to $040400-$047FFF (in RAM)
3. **Shadow RAM size**: Typically 32-48 KiB depending on TOS version and model

```
STE Shadow RAM mapping:
$040000 ┌─────────────┐$040400  RAM (expanded with STE BIOS)
         │  Shadow RAM  │
$048000  ├─────────────┤$048400  RAM region
         │  (Shadowed   │
         │   ROM data)  │
```

### CE# / OE# Timing Diagram

```
Chip Enable (CE#) and Output Enable (OE#) Timing:

CE#  _______________-------------------------------------
           ↓                ↑
           ├── tCE ──→     Data valid
           (CE# asserted)  (after tCE/tA delay)

OE#  ___________________--------------------------------
            ↓              ↑
            ├── tOE ──→   Data valid
            (OE# asserted)

Data   ────────────────[DATA]──────────────────────────
              ↑        ↑
              tCE     tOE
              (earlier wins)

Note: The 27256 outputs data when BOTH CE# AND OE# are LOW.
      The shorter of tCE and tOE determines effective
      access timing. Data remains valid for tOH after either
      signal goes HIGH (turns off).
```

### 68000 Read Cycle vs. ROM Timing (12.5 MHz ST)

```
68000 at 12.5 MHz (T = 80 ns per clock):

Phase  E1 (12.5 MHz)    E2 (12.5 MHz)
      ┌───────┐           ┌───────┐
/E  ──┘       └───────────┘       └──

Address stable at ────────┐
                          │  tA (ROM access time)
Data available   ─────────┼────── [DATA] ───
                          │           ↑
                          └───────────┘
                           68000 samples data
                           during E2 phase

Typical worst case:
  tA(5V 27256) = 250 ns (150 ns typical)
  68000 E-cycle = 2 x 80 ns = 160 ns minimum

  Timing margin is tight. The ST ROM uses 250 ns (5V)
  devices with guaranteed access within the 68000's
  E-cycle budget, relying on:
    1. ROM being accessed for full E-cycle duration
    2. ROM tCE/tOE being the limiting factor
    3. Address setup already complete before /E falls
```

### Version Detection in Code

```
Detecting TOS version:
  Read byte at $FF0010: "TOS "
  Read byte at $FF0014: Major version / 10
  Read byte at $FF0015: Minor version / 10

Example: "TOS  1.62"
         ^^^^^^^
         $FF0010 = "TOS  "
         $FF0014 = 0x31 (major = 31 / 10 = 3, or $16 / 10 = 1)
         $FF0015 = 0x36 (minor = 36 / 10 = 3, or $62 / 10 = 6)

Note: TOS versions use packed decimal format:
  1.06 → bytes $31 $36 $32
  2.06 → bytes $32 $36 $36  
  3.06 → bytes $33 $36 $36
```

## 8. Emulation Notes

### STeem Architecture ROM Emulation

STeem emulates the Atari ST ROM 27256 as follows:

#### ROM Loading

```
┌────────────────────────────────────────────────────────┐
│              STeem ROM Loading Flow                     │
├────────────────────────────────────────────────────────┤
│                                                        │
│  1. User provides TOS ROM file(s) via settings         │
│     (e.g., STeem settings → TOS ROM path)             │
│                                                        │
│  2. STeem reads ROM file into memory buffer:           │
│     rom_buffer[32768] or larger                        │
│                                                        │
│  3. ROM buffer is mapped into the emulated CPU:        │
│     CPU memory space at $FF0000-$FFFFFF                │
│                                                        │
│  4. Read handlers intercept ROM region:                │
│     - Any read to $FF0000-$FFFFFF → returns from       │
│       rom_buffer[address & 0x7FFF]                     │
│                                                        │
│  5. STE dual-ROM:                                      │
│     - BIOS1 maps to $FF0000-$FFBFFF                    │
│     - BIOS2 maps to $FFC000-$FFFFFF                    │
│     - Reads span both with correct addressing            │
│                                                        │
│  6. MegaSTE:                                           │
│     - Single 64 KiB BIOS image                         │
│     - Maps to $FF0000-$FFFFFF (expanded)               │
│                                                        │
│  7. ROM shadowing emulation:                           │
│     - Copy ROM region to RAM shadow area ($040400+)    │
│     - Switch ROM reads to RAM reads for performance    │
│     - Shadow copy used for critical paths (boot)       │
└────────────────────────────────────────────────────────┘
```

#### Key Emulation Details

**ROM Region Interception:**

```
Emulated CPU Memory Space:

┌─────────────────────────────────────────────────────┐
│  $FF0000 - $FFFFF                                    │
│  ┌─────────────────────────┐                         │
│  │ ROM region interception  │                        │
│  │ (CPU_MEM_READ hook)     │                        │
│  │                         │                        │
│  │ If address in ROM zone: │                        │
│  │   return rom_data[offs] │                        │
│  │                         │                        │
│  │ Else fall through to:   │                        │
│  │   return real_ram[...]  │                        │
│  └─────────────────────────┘                         │
├─────────────────────────────────────────────────────┤
│  $000000 - $EFFFFF                                   │
│  Real RAM (dynamically allocated)                    │
└──────────────────────────────────────────────────────┘
```

**Boot Process Emulation:**

```
Emulated Boot Sequence:

1. 68000 reset vector at $000000-0003
   - Initial stack pointer: $00FFFFFC
   - Entry point: $000004 → jump to $FFFFFFFC

2. $FFFFFFFC → ROM boot vector
   - Initialize system parameters
   - Detect hardware (ST vs STE)
   - Load TOS from ROM buffer

3. $FF0014-$FF0015 → Read version string
   - Determine TOS version (1.x, 2.x, 3.x)
   - Select compatible boot path

4. Execute ROM init code:
   - $FF8000+ → ST-Kernel entry
   - Initialize GEMDOS, MMIO, BIOS
   - Start GEM/AES

5. STE-specific boot:
   - Check BIOS1/BIOS2 checksums
   - Initialize STE hardware (blitter, ACIA)
   - Shadow ROM to RAM
   - Copy BIOS2 into place
```

**ROM Data Access Patterns in Emulation:**

```
Common emulation ROM access patterns:

Access Type          Address           Purpose
─────────          ───────           ───────
Version check      $FF0010-$FF0015   Read TOS version string
Boot entry          $FF8000           ST-Kernel entry point
Vector table        $FFFFFE0+$       Boot vector table
GEMDOS entry        $FF8700           GEMDOS base
Kernel entry        $FF877A           LWSSYSG entry
BIOS functions     $FF8000-$FF87FF   BIOS1 functions
STE init           $FFC000-$FFFFFF   STE extensions

Emulation must handle:
  - Unaligned 68000 bus cycles (split word accesses)
  - Byte vs word vs long access alignment
  - Bank switching ($FF0000 vs $FFFF0000)
  - ROM shadow state transitions
```

**Important Emulation Considerations:**

1. **ROM size matching**: Ensure the loaded ROM file matches the expected size. If the file is smaller than the emulated region, pad with `0xFF` bytes (the natural state of erased/unprogrammed EEPROM locations).

2. **Checksum validation**: STeem can validate ROM checksums against known values. Invalid checksums indicate a corrupted or incorrectly mapped ROM.

3. **Dual-ROM boundary**: For STE mode, the BIOS1/BIOS2 boundary is at $FFC000. A single 32 KiB ROM should only be mapped to BIOS1. A full STE BIOS requires both BIOS1 and BIOS2.

4. **ROM shadowing state**: After STE ROM_SHAD executes, the $FF0000-$FFFFFF region reads from shadow RAM instead of the ROM buffer. This must be tracked in emulation state.

5. **TOS version-dependent behavior**: Different TOS versions have different:
   - GEMDOS function addresses
   - Stack pointer values at boot
   - BIOS entry/exit conventions
   - Supported floppy formats (DD vs MQ)
   - Keyboard driver (in-system vs external)

6. **MegaSTE 27C512 compatibility**: While the MegaSTE uses a 27C512 (64 KiB, CMOS), emulation should accept standard TOS 3.x ROM images and map them correctly. The physical difference (UV EPROM vs EEPROM) does not affect emulation.

7. **ROM timing in emulation**: STeem does not emulate 27256 access timing precisely (ROM is accessed with 0 or 1 cycle latency). Real hardware has 150-250 ns access time, but since the ROM is within the same clock domain as the 68000, and the E-cycle covers the full access window, no timing delays are strictly necessary for functional correctness.

### Common ROM Issues in Emulation

| Issue | Cause | Solution |
|-------|-------|----------|
| Boot loop | Wrong ROM checksum / corrupted data | Use valid TOS ROM file, verify checksum |
| GEM crashes | ROM data at wrong addresses | Check ROM file offset/mapping |
| TOS version wrong | Version string at $FF0010 mismatched | Correct TOS ROM version file |
| STE features missing | Only BIOS1 loaded, BIOS2 missing | Load both BIOS1 and BIOS2 images |
| Screen garbage during boot | Shadow RAM region overlaps display | Check shadow RAM address conflicts |
| Floppy not detected | TOS version doesn't support MQ format | Use TOS 1.42 or later |
