# Atari ST DRAM Chips – 41256 and 414616

## 1. Overview of DRAM in Atari ST

The Atari ST series uses **Dynamic RAM (DRAM)** chips for its main system memory. DRAM was chosen because it offered the highest density-per-pin and lowest cost-per-bit available in the mid-1980s, which was critical for fitting 256 KB (and later 640 KB) of RAM into the limited pin count and budget of a consumer computer at that price point.

The ST range uses **16-pin DIP dual in-line package** DRAM chips on a single-bit-plane architecture:

| Chip part number | Density  | Organization | Manufacturer(s)        |
|------------------|----------|--------------|------------------------|
| HM62256 / 41256  | 256 Kbit | 256K × 1     | Hitachi, Toshiba, etc. |
| HM6216 / 41416   |  64 Kbit |  64K × 1     | Hitachi, Toshiba, etc. |

The **414616** name referenced in documentation is an alternate/marketing designation for the **64K × 1** DRAM (equivalent to Hitachi HM6216 / Cypress CY6216 / Samsung KM4164). The "41" prefix denotes a dynamic RAM family from multiple vendors.

### Why DRAM instead of SRAM?

- **Cost:** In 1985, SRAM cost roughly 5–10× more per bit than DRAM.
- **Density:** 16-pin DIP SRAM could only reach ~1 KB, while DRAM achieved 64 Kbit and 256 Kbit.
- **Interface simplicity:** The ST used a single **RAS** (Row Address Strobe) and **CAS** (Column Address Strobe) multiplexing scheme, requiring only ~20 address lines from the CPU instead of 256+ pins for a full address bus.

The ST's memory system has **3 banks**:

| Bank   | Size          | Purpose                    |
|--------|---------------|----------------------------|
| Bank 0 | 256 KB (ST)   | Standard user RAM          |
| Bank 1 | 256 KB (ST)   | Expandable (256→512 KB)   |
| Bank 2 (VTB) | 4 KB   | Video Frame Buffer (shared between CPU and TMS9918 VDP) |

## 2. 41256 DRAM Chip – Detailed Specification

The **41256** (also marketed as HM62256, M52256, 41256AJ-15, etc.) is a **256 Kbit** DRAM chip and is the primary DRAM used in the original **ST** and **STe** (Bank 1 of STe) memory configurations.

### Pinout (16-pin DIP, top view)

```
         ┌─────────────┐
    NC  1│*            16│ VCC (+5V)
   A6     2│            15│ A4
   A5     3│            14│ DQ (I/O)
   A3     4│            13│ DQ (I/O)
  A10     5│            12│ NC
   A0     6│            11│ A1
   A1     7│            10│ A3
A9/AFC *  8│            9 │ A5
         └─────────────┘

* Pin 8 is AFC (Automatic Frequency Change) on original Samsung/Hitachi parts,
  internally tied high (A9) with a 100 nF capacitor to VCC in ST designs.
```

Detailed pin table:

| Pin | Name   | Direction | Description                          |
|-----|--------|-----------|--------------------------------------|
| 1   | NC     | –         | No connect (internally floating)     |
| 2   | A6     | In        | Row address bit 6                    |
| 3   | A5     | In        | Row address bit 5                    |
| 4   | A3     | In        | Row address bit 3                    |
| 5   | A10    | In        | Row address bit 10                   |
| 6   | A0     | In        | Row address bit 0 (multiplexed)      |
| 7   | A1     | In        | Row address bit 1 (multiplexed)      |
| 8   | A9/AFC | In        | Row address bit 9 (or AFC signal)    |
| 9   | A5     | In        | Row address bit 5 (multiplexed)      |
| 10  | A3     | In        | Row address bit 3 (multiplexed)      |
| 11  | A0     | In        | Row address bit 0 (multiplexed)      |
| 12  | A1     | In        | Row address bit 1 (multiplexed)      |
| 13  | DQ     | Bi-dir    | Data input/output (bit 0 of chip)    |
| 14  | DQ     | Bi-dir    | Data input/output (bit 0 of chip)    |
| 15  | A4     | In        | Row address bit 4                    |
| 16  | VCC    | Power     | +5V supply                           |

Rows 1 (NC), 9/10 (A3), and 11/12 (A0/A1) are **multiplexed address pins** – their function depends on the RAS/CAS phase.

## 4. DRAM Arrangement on Original ST Motherboard

The original **ST520 STe/STe** (and ST4STe) motherboard uses a **Bank 0 + Bank 1** configuration for 256 KB or 512 KB of main memory.

### ST Motherboard DRAM Chip Layout

```
+----------------------------------------------------------+
|                                                          |
|   [Y12] [Y13] [Y14] [Y15]   Bank 0 – 256K × 1 × 8      |
|   (8 × 41256-15 DIP-16 chips)                            |
|                                                          |
|   [Y8]  [Y9]  [Y10] [Y11]   Bank 1 – 256K × 1 × 8      |
|   (8 × 41256-15 DIP-16 chips)                          |
|                                                          |
|                              [U25]                       |
|   (4 × HM6265 512B × 8 FIFO / 1 bit × 4096)             |
|   Bank 2 – VTB Frame Buffer 4 KB                         |
|                                                          |
|   CPU: Motorola 68000 @ 7.16 MHz (NTSC) / 8.0 MHz (PAL)  |
|   AINT (Auto Intermittent) DRAM refresh                  |
|                                                          |
|   1 Bit Plane: 8 chips (one per DRAM bit per bank):      |
|     Bank 0:  U9,U10,U11,U12,U13,U14,U15,U16             |
|     Bank 1:  U1-U8                                      |
+----------------------------------------------------------+
```

### ST DRAM Configuration Table

```
+-------------------+----------+----------+---------------------------+
| Model             | RAM size | Bank 0   | Bank 1                    |
+-------------------+----------+----------+---------------------------+
| ST520 / STF       | 256 KB   | 256 KB   | Not populated             |
| STe               | 512 KB   | 256 KB   | 256 KB                    |
| Mega ST           | 512 KB   | 256 KB   | 256 KB                    |                     |
| STFM (512 KB)     | 512 KB   | 256 KB   | 256 KB                    |
| STFM (256 KB)     | 256 KB   | 256 KB   | Not populated             |
| STE (512K)        | 512 KB   | 64 KB    | 64 KB                     |
| STE (1 MB)        | 1024 KB  | 128 KB   | 128 KB                    |
+-------------------+----------+----------+---------------------------+
```

### ST Bank 0 – 256K × 1 Chip Set (one bit plane, each chip supplies 1 bit):

```
Bank 0 (256 KB = 256K × 8 bits):
  Bit 0:  U9  (41256-15)
  Bit 1:  U10 (41256-15)
  Bit 2:  U11 (41256-15)
  Bit 3:  U12 (41256-15)
  Bit 4:  U13 (41256-15)
  Bit 5:  U14 (41256-15)
  Bit 6:  U15 (41256-15)
  Bit 7:  U16 (41256-15)
  Total: 8 × 41256-15 = 256K × 8 bits = 256 KB
```

- **Address lines:** A0–A17 from CPU (A0–A15 from the Bus Interface Unit, BIU)
- **Data lines:** D0–D7 from CPU → 8 DRAM chip data outputs per bank → BIU
- **Bank select:** `/BSEL0` and `/BSEL1` from the BIU (GS00, GS01) determine which 256 KB bank is selected
- **CAS RAS:** The ST uses the `/CAS` signal (BIU generated) for both banks simultaneously
- **RAS:** The `/RAS` signal is driven by the BIU (specifically the GS00/GS01 decoder)

## 5. DRAM Arrangement on STe Motherboard

The **STe** has a **different memory architecture** from the original ST. The STe integrates most of the original ST's glue logic into three LSI chips, including DRAM control into **GS02 (BIU)**.

### STe DRAM Configuration

```
+----------------------------------------------------------+
|                                                          |
|   STe Memory Map:                                        |
|   +--------------------------------------------------+  |
|   |  Bank A: 64 KB (64K × 8)    – Uses 41416 (64K×1) |  |
|   |     Chips: U31-U38 (8 × 41416-15)                |  |
|   +--------------------------------------------------+  |
|   |  Bank B: 64 KB (64K × 8)    – Uses 41416 (64K×1) |  |
|   |     Chips: U25-U32 (8 × 41416-15)                |  |
|   +--------------------------------------------------+  |
|   |  Bank C: 128 KB (128K × 8)  – Uses 41256 (256K×1)|  |
|   |     Chips: U43-U50 (8 × 41256-12 or 41256-15)    |  |
|   +--------------------------------------------------+  |
|   |  Bank D: 128 KB (128K × 8)  – Uses 41256 (256K×1)|  |
|   |     Chips: U55-U62 (8 × 41256-12 or 41256-15)    |  |
|   +--------------------------------------------------+  |
|   |  VTB Frame Buffer: 4 KB (HM6265 × 4)              |  |
|   +--------------------------------------------------+  |
|   Total: 64 + 64 + 128 + 128 = 384 KB + 4 KB VTB      |
|   Actually: 512 KB = 64+64+128+128+64+64              |
+----------------------------------------------------------+
```

Corrected STe memory layout:

```
+----------------------------------------------------------+
|  Bank 0: 64 KB  (64K × 8) → 8 × 41416 (64K × 1)        |
|  Bank 1: 64 KB  (64K × 8) → 8 × 41416 (64K × 1)        |
|  Bank 2: 128 KB (128K × 8) → 8 × 41256 (256K × 1)      |
|  Bank 3: 128 KB (128K × 8) → 8 × 41256 (256K × 1)      |
|  Bank 4: 64 KB  (64K × 8) → 8 × 41416 or 41256         |
|  Bank 5: 64 KB  (64K × 8) → 8 × 41416 or 41256         |
|  VTB:     4 KB          → 4 × HM6265 (512 × 8)          |
+----------------------------------------------------------+
|  Total = 512 KB + 4 KB VTB                              |
+----------------------------------------------------------+

Pinout for 41416 (64K × 1):
  Row: 8 rows (A0-A7) on pins 2,3,4,5,6,7,8,9
  Col: 8 cols (A0-A7) on pins 10,11,12,13,14,15,16,pins1-2 (multiplexed)
```

The STe's **68000-compatible BIU in the GS02 chip** manages DRAM access with **burst mode** and **interleaved bank access**. The critical architectural change from the ST to the STe is:

1. The STe uses **banked memory** (6 banks of 64 KB each instead of 2 banks of 256 KB each).
2. The **automatic DRAM refresh** is now handled internally by the GS02 BIU (the ST used a dedicated logic circuit with a 60 Hz / 50 Hz refresh clock tied to the vertical sync).
3. The STe supports **640 KB total**: 512 KB user RAM + 4 KB VTB + 128 KB reserved.
4. The STe uses both **41416 (64K × 1)** and **41256/41256 (256K × 1)** chips in its different banks.

The STe also uses **41256** chips in **Bank 3** and **Bank 4** for its 512 KB configuration:

```
STe 512 KB memory:
  Bank 0: 8 × 41416 (64K × 1)  → 64 KB
  Bank 1: 8 × 41416 (64K × 1)  → 64 KB
  Bank 2: 8 × 41256 (256K × 1) → 128 KB (uses addresses A0-A17, rows 0-255)
  Bank 3: 8 × 41256 (256K × 1) → 128 KB
  Bank 4: 8 × 41416 (64K × 1)  → 64 KB
  Bank 5: 8 × 41416 (64K × 1)  → 64 KB
  ===== 512 KB total
```

## 7. Row/Column Address Multiplexing

DRAM chips use **address multiplexing** to reduce the number of Pins needed. The 41256 and 41416 both have pins that carry either row or column addresses at different phases of the access cycle.

### How address multiplexing works on 41256 (256K × 1):

```
Internal DRAM matrix: 512 rows × 512 columns = 256 Kbits

Phase 1 - RAS LOW (Row Address Strobe active):
  Row address is latched into the row address register via:
    Pin 2:  A6
    Pin 3:  A5
    Pin 4:  A3
    Pin 5:  A10
    Pin 6:  A0
    Pin 7:  A1
    Pin 8:  A9
    Pin 15: A4
  Total row address = 512 (9 explicit pins + 2 multiplexed pins = 512 rows)

Phase 2 - RAS goes HIGH, then CAS LOW:
  Column address is latched into the column address register via:
    Pin 6:  A0  (now column A0)
    Pin 7:  A1  (now column A1)
    Pin 11: A0 (now column A2)
    Pin 12: A1 (now column A3)
    Pin 8:  A9 (now column A4-A7, via AFC circuit)
    Pin 9:  A5  (now column A5)
    Pin 10: A3  (now column A6)
    Pin 15: A4  (now column A7)
  Total column address = 512 (8 pins = 512 columns)

During Phase 1, pins 6,7,11,12,15 carry ROW addresses.
During Phase 2, pins 6,7,9,10,11,12 carry COLUMN addresses.
The same pins carry different addresses at different times.
```

### Internal matrix mapping for 41256:

```
Row decode (9 bits):  Pins 2(A6),3(A5),4(A3),5(A10),6(A0),7(A1),8(A9),15(A4)
                       + pin 9(A5)/pin 10(A3) during RAS phase → effectively
                       Row:  2^9 = 512 rows  ×  512 columns = 262144 bits

  Row address pins during RAS LOW:
    A0 = Pin 6
    A1 = Pin 7
    A3 = Pin 4 (row) / Pin 10 (column)
    A4 = Pin 15
    A5 = Pin 3 (row) / Pin 9 (column)
    A6 = Pin 2
    A9 = Pin 8
    A10 = Pin 5
    (A2 is implied / tied to internal circuit)
```

### Internal matrix mapping for 41416 (64K × 1):

```
Internal DRAM matrix: 256 rows × 256 columns = 64 Kbits

Row decode (8 bits):  Pins 2(A6),3(A5),4(A3),5(A10),6(A0),7(A1/A2),8(A9)
    + Pin 15(A4) → 2^8 = 256 rows

Column decode (8 bits):
    Pin 6 (A0), Pin 7 (A1), Pin 11 (A2), Pin 12 (A3),
    Pin 8 (A4-A7 via AFC), Pin 9 (A5), Pin 10 (A6), Pin 15 (A7)
    2^8 = 256 columns

  Column address pins during CAS LOW:
    A0 = Pin 6
    A1 = Pin 7
    A2 = Pin 11
    A3 = Pin 10 (col) / Pin 4 (row)
    A4 = Pin 8 (via AFC)
    A5 = Pin 9 (col) / Pin 3 (row)
    A6 = Pin 15 (col)
    A7 = Pin 8 (AFC)
```

## 8. DRAM Refresh Mechanism

DRAM cells lose their charge over time and must be periodically **refreshed**. The Atari ST handles this in two different ways depending on the model.

### Original ST (ST/STe) – AINT (Auto Intermittent) Refresh

```
+------------------------+
|   AINT (Auto Intermittent)   |
|   DRAM Refresh System          |
+----------------------------+

The ST uses a **60 Hz (NTSC) or 50 Hz (PAL)** periodic refresh cycle
that is phase-locked to the vertical blank interval:

  +--------------------+
  | Vertical Sync (VBI) |  ← 15.625 kHz (NTSC) or 15.621 kHz (PAL)
  | (from Blitter / TIA) |
  +--------------------+
         |
         | Gates the refresh clock
         v
  +--------------------+
  | 60 Hz refresh clock |  (NTSC) or 50 Hz (PAL)
  | generated from     |
  | 3.58 MHz / 4.43 MHz |
  +--------------------+
         |
         | /REF or /AINT signal
         v
  +--------------------+
  | ST BIU (GS01/GS02)  |
  | Each /AINT pulse =  |
  |  DRAM row refresh   |
  +--------------------+
         |
         v
  +--------------------+
  | DRAM banks (Bank0, Bank1) |
  | All /RAS goes LOW for a  |
  | brief moment (refresh)   |
  +--------------------+

Refresh period:  15.625 µs (NTSC) or 20.000 µs (PAL)
Rows per refresh:  512 (41256) or 256 (41416)
```

In the original ST, the **BIU (GS01/GS02)** generates DRAM refresh pulses derived from the **CRT VBI sync signal** via the TIA/Blitter. This ensures that DRAM refresh occurs during the **vertical blank interval** when the CRT is not actively drawing, preventing visible artifacts.

Each `/AINT` signal triggers a **refresh cycle** that:
1. Latches the current row address internally
2. Recharges all cells in that row
3. Advances to the next row
4. Cycles through all rows (512 for 41256, 256 for 41416) before repeating

### STe – Integrated BIU (GS02) Internal Refresh

```
+----------------------------------------------------+
|  STe GS02 BIU Internal DRAM Controller              |
+----------------------------------------------------+

  The STe's GS02 chip has a built-in DRAM controller with:
  
  1. Auto-refresh counter (8 bits, counts 0-255)
  2. Refresh clock generator (derived from CPU clock / 2)
  3. CAS/RAS timing generator
  
  Refresh mode:
    - Auto-refresh: ~15.6 µs (NTSC) or ~20 µs (PAL)
    - Each STe bank is refreshed independently
    - Banks 0-5 are refreshed sequentially
    - VTB (bank 2) is refreshed separately via VBI
  
  The STe BIU generates:
    - /RAS pulses for each bank at its own timing
    - /CAS pulses with proper tRCD timing
    - Burst mode DRAM access (sequential rows)
    - Bank interleaving (while one bank refreshes, 
      others can be accessed)
```

The STe's internal refresh is more sophisticated: each of the **6 memory banks** has its own refresh counter, allowing **bank interleaving** – one bank can be refreshed while another is being accessed by the CPU.

### Refresh Cycle Detail:

```
DRAM Cell Structure (simplified):
+----------------+
|  Capacitor     |  ← stores a bit (charged = 1, discharged = 0)
+----------------+
| Sense Amplifier |  → detects and amplifies the weak signal
+----------------+
| Row Decoder     |  → selects row
+----------------+
| Column Decoder  |  → selects column within row
+----------------+

Read = destructive: reading a cell discharges it.
Refresh: read each cell in a row, then rewrite the same value.

ST refresh cycle (41256, 512 rows):
  Row 0 → refreshed
  Row 1 → refreshed
  ...
  Row 511 → refreshed
  (then repeat from Row 0)

  Time for full refresh = 15.625 µs (NTSC) or 20 µs (PAL)
  Average time between refreshes per row = 15.625 µs

  64K x 1 (41416) has 256 rows:
  Time for full refresh = 4.096 ms (standard JEDEC spec)
  But in ST context, it's still refreshed at 15.625 µs intervals
  (the ST's refresh logic forces it, even though 41416 spec is slower)
```


## 10. Emulation Timing Requirements

For ST emulation (STeem and other emulators), the DRAM timing directly affects **emulation accuracy**, **performance**, and **compatibility**.

### Minimum DRAM Access Cycles:

```
+------------------------------------------------------------+
|  Emulator DRAM Timing Model (per memory access type)       |
+------------------------------------------------------------+

1. Normal sequential access (BIU internal bus):
   Rows 0-255 or 0-511 (Bank 0 or 1):
     First access:  2-3 CPU cycles (130ns + tRCD + tAC)
                        = 2-3 ST cycles @ 7.16 MHz
     Sequential:    1 CPU cycle per DRAM word
   
   Bank 1:
     First access:  2-3 CPU cycles
     Sequential:    1 CPU cycle per DRAM word

2. Bank switch access (Bank 0 → Bank 1 or vice versa):
   Bank select change overhead:  1 extra CPU cycle
   
   Bank 0 → Bank 1:  2 → 1 → 2 (SETUP + transfer) cycles
   Bank 1 → Bank 0:  2 → 1 → 2 (SETUP + transfer) cycles

3. VTB (Video Frame Buffer) access:
   4KB shared with TMS9918 VDP:
     VDP access:   1-2 CPU cycles (VDP has priority)
     CPU access:   2-4 CPU cycles (may stall if VDP accessing)
   
   During vertical blank:  CPU has no contention → faster access
   During display:        CPU may be stalled by VDP

4. STe Burst mode (68000 external bus cycles):
   First word in burst:  ~105 ns = 1.5 CPU cycles
   Subsequent words:     ~30 ns = 0.4 CPU cycles (internal buffer)

5. Refresh overhead:
   Each DRAM refresh takes:  ~18 CPU cycles per row
   ST:  15.625 µs between refreshes → ~112 cycles between
   Total refresh overhead:  ~2-3% of CPU time
```

### Common emulation pitfalls:

```
1. NOT accounting for CAS/RAS timing differences between 41256-15 and 41256-12
   - 150 ns vs 120 ns → significant in precise timing demos
   
2. NOT implementing refresh at correct intervals
   - 15.625 µs (NTSC) or 20.0 µs (PAL)
   - Missing refresh → data corruption in real hardware
   
3. NOT handling bank-select transitions correctly
   - ST switches Bank 0 ↔ Bank 1 every few KB (bank switching in DOS)
   - Each switch costs 1 extra CPU cycle
   
4. NOT accounting for VTB contention
   - Real ST CPU stalls when VDP accesses VTB simultaneously
   - Critical for graphics demos and timing-critical games
   
5. NOT correctly multiplexing addresses on DRAM pins
   - STe address decoding differs from original ST
   - Different address ranges map to different banks
```

### Cycle-accurate DRAM access model for emulators:

```
For accurate ST emulation (cycle-accurate bus simulation):

struct DramAccess {
    uint32_t address;     // CPU address
    uint8_t  bank;        // 0 or 1 (ST), 0-6 (STe)
    bool     is_read;     // Read or write
    uint32_t latency;     // Cycles until data ready
};

// ST memory access (simplified):
uint32_t calculate_dram_latency(uint32_t address) {
    uint8_t bank = (address >> 18) & 1;  // Bit 18 selects bank 0/1
    uint32_t prev_bank = last_accessed_bank;
    
    if (bank != prev_bank) {
        return 3;  // Bank switch overhead (2 cycles setup + 1 access)
    }
    // Check if sequential from previous access
    if (address == prev_address + 1) {
        return 1;  // Sequential access, no extra latency
    }
    return 2;  // Non-sequential access (RAS/CAS setup)
}

// STe with burst mode:
uint32_t calculate_ste_dram_latency(uint32_t address) {
    uint8_t bank = (address >> 16) & 7;  // Bits 16-18 select bank 0-6
    // GS02 handles burst mode transparently
    // First word: 2 cycles, subsequent: ~0.4 cycles each (interleaved)
    if (is_burst_sequence(address)) {
        return 2;  // First word
    }
    return 1;  // Subsequent burst word
}
```
