# GST MCU C302183

> The Atari GST MCU (Glue + Memory Control Unit) C302183 is the central ASIC of the Atari STe and Mega STE, integrating four custom chips into one 144-pin package.

## Overview

### What Is the GST MCU C302183?

The GST MCU (part number **C302183-002**) is a custom gate-array ASIC manufactured by GST (General Semiconductor Technology, later acquired by VLSI Technology) under contract for Atari. It replaced the four separate custom chips used in the original Atari ST (Glue C029144, MMU C028300, DMA C029128, plus part of Shifter functionality) with a single SMT (surface-mount technology) 144-pin PLCC package.

### Models Using This Chip

| Model | Release | GST MCU Variant | Other Chips | Notes |
|-------|---------|----------------|-------------|-------|
| Atari STe 520 | 1989 | C302183-001 (no blitter) / C302183-002 | GST Shifter C029145 (PLCC144) | First ST with STe chips |
| Atari STe 1040 | 1989 | C302183-002 | GST Shifter C029145 (PLCC144) | Full-size STe |
| Mega STE | 1991 | C302183-002 | SH2 C301842 (PLCC68), GST Shifter C029145 (PLCC144) | Added SH2 for 16 MHz + IDE |

Two variants of the C302183 exist:
- **C302183-001**: GST MCU without the blitter (used in early STe prototypes or specific OEM versions)
- **C302183-002** (or C301157-002, C303075): GST MCU **with** integrated blitter (used in production STe and Mega STE)

### Why Replace GLUE + MMU + DMA + Part of Shifter?

The original Atari ST (1985) distributed system control across **four custom PLCC68 chips**:
1. Glue (C029144) - system glue logic, DRAM control, video timing
2. MMU (C028300) - memory management, DRAM refresh, scroll
3. DMA (C029128) - bus arbitration and DMA control
4. Shifter (C028787/C028761) - video display controller

By 1989, SMT manufacturing had matured. Consolidating onto fewer, larger chips offered:
- **Smaller board space** - enabling the compact STe chassis
- **Lower component count** - fewer failure points, lower BOM cost
- **Reduced signal paths** - internal bus connections are on-chip (faster, less noise)
- **New features** - the STe needed integrated blitter, stereo DAC, color PAL, Super Hi-Res, joystick/paddle/pen ADC, all of which required additional logic that fit naturally inside the GST MCU

| Aspect | Original ST (4 chips) | STe (2 chips) |
|--------|----------------------|---------------|
| Total custom chips | 4 x PLCC68 | 2 x PLCC144 |
| Total pins | ~272 | ~288 (but many shared/internal) |
| Board area occupied | ~4 chips, spread out | 2 chips, centralized |
| SMT vs DIP | PLCC (SMT) | PLCC (SMT only) |
| Blitter | None | Integrated in GST MCU |

### Functional Blocks

The GST MCU contains five major functional divisions:

| Block | Replaces | Description |
|-------|----------|-------------|
| **GLUE Block** | Glue chip (C029144) | System glue logic, clock generation, address decoding, DRAM row/col timing |
| **MMU Block** | MMU chip (C028300) | Page mapping, scroll registers, DRAM row counter, MAD (DRAM address) output |
| **DMA Block** | DMA chip (C029128) | Bus arbitration, DMA address/counter control for floppy and ACSI transfers |
| **Blitter Engine** | None (new) | 2-bit block transfer engine with 16 Boolean ops, halftone RAM, skew |
| **I/O Block** | New | Joystick/paddle/pen ADC, serial I/O, new STe-specific signal generation |

### MMU Block Registers

The MMU block registers in the STe are the same as the original STMMU, accessed through a dedicated MMU access cycle (not memory-mapped in the conventional sense):

| Register | Address (MMU cycle) | Size | Description |
|----------|-------------------|------|-------------|
| Scroll 0 | $FFE000 | 12 bits | Scroll digit 0 (fine horizontal/vertical) |
| Scroll 1 | $FFE002 | 12 bits | Scroll digit 1 |
| Scroll 2 | $FFE004 | 12 bits | Scroll digit 2 |
| Scroll 3 | $FFE006 | 12 bits | Scroll digit 3 |
| Scroll 4 | $FFE008 | 12 bits | Scroll digit 4 |
| Scroll 5 | $FFE00A | 12 bits | Scroll digit 5 |
| Scroll 6 | $FFE00C | 12 bits | Scroll digit 6 |
| Scroll 7 | $FFE00E | 12 bits | Scroll digit 7 |

These are **not memory-mapped** in the traditional sense. The MMU scroll registers are accessed by writing to or reading from the address range $FFE000-$FFE0FF while the address is also the scroll register address. The CPU uses the **MMU mode cycle** to write/read scroll values.

### GST MCU Page Mapping Registers

The STe GST MCU replaces the original ST MMU page mapping with **programmatic page mapping** via the GST MCU internal registers. The page mapping determines which physical RAM page appears at each logical page location.

| Register | Location | Size | Description |
|----------|----------|------|-------------|
| Page Map Registers | Inside GST MCU | 32 x 16 bits | 32-entry page mapping table |
| Page Map Enable | Inside GST MCU | 1 bit | Page mapping enable/disable |

The page mapping mechanism maps physical DRAM locations to logical address space, enabling memory banking beyond the ST's fixed mapping.

## Memory Addressing and Refresh

### DRAM Refresh Mechanism

The GST MCU generates DRAM refresh signals autonomously, independent of the 68000 CPU:

```
GST MCU DRAM Refresh Sequence:

+-----+     +--------+     +---------+     +--------+
| Refresh   |    | Row Addr |    | RAS     |    | CAS     |
| Counter   |--> | (10-bit) |--> | Strobe  |--> | Strobe  |
| (10-bit)  |    +--------+     +---------+     +--------+
+-----+         | MAD0-MAD9 |                          |
                +-----------+                          v
                                              +-----------+
                                              | MAD10-MAD11|
                                              | (CAS Addr) |
                                              +-----------+
                                                    |
                                                    v
                                               +-----------+
                                               | 68K CPU   |
                                               | Bus Grant |
                                               | Signal    |
                                               +-----------+
```

| Parameter | Value | Notes |
|-----------|-------|-------|
| Refresh counter width | 10 bits | Counts 0 to 1023 |
| Rows per refresh cycle | 1024 | Full DRAM refresh |
| Refresh period | ~4 ms | Per full cycle of all rows |
| Per-row refresh time | ~3.9 us | 4 ms / 1024 rows |
| MAD output | 12 bits | MAD0-MAD9 to DRAM row, MAD10-MAD11 to CAS |

### DRAM Address Signal (MAD)

The GST MCU outputs the **MAD** (Memory Address Data) bus to the DRAM chips:

| MAD Signal | Function |
|-----------|----------|
| MAD0-MAD9 | Row address lines (10 bits, selects one of 1024 rows) |
| MAD10-MAD11 | Row address (bits 10-11, used with MAD0-9 for row during CAS) |
| MAD12-MAD14 | Column address lines (3 bits, selected by CAS timing) |

The MAD bus serves dual purpose:
1. During RAS phase: MAD0-MAD11 = row address
2. During CAS phase: MAD12-MAD14 = column address

### Memory Bank Selection

The STe uses a **page mapping table** (32 entries, 16 bits each) inside the GST MCU. Each entry maps an 32 KB logical page to a physical DRAM bank:

```
Physical DRAM Layout (1040STE, 4 MB):

  Bank 0: $000000-$03FFFF  (256 KB, physical page 0)
  Bank 1: $040000-$07FFFF  (256 KB, physical page 1)
  Bank 2: $080000-$0BFFFF  (256 KB, physical page 2)
  Bank 3: $0C0000-$0FFFFF  (256 KB, physical page 3)
  Bank 4: $100000-$13FFFF  (256 KB, physical page 4)
  ...
  Bank 15: $3C0000-$3FFFFF (256 KB, physical page 15)
  Bank 16: $400000-$43FFFF (256 KB, physical page 16)
  ...
  Bank 31: $7C0000-$7FFFFF (256 KB, physical page 31)

GST MCU Page Map Table (32 entries):
  Entry N = physical page number that should appear at logical page N
  0x00 = map logical page 0 to physical page 0 (identity)
  0x1F = map logical page 0 to physical page 31
```

On a page-mapped STe:
- Reset sets up identity mapping (page 0 -> physical page 0, etc.)
- TOS can reprogram page map via GST MCU registers
- Video RAM is always mapped to a known logical region ($A0000-$A7FFF)

### Video RAM Mapping

| Mode | Video RAM region | Description |
|------|----------------|-------------|
| All ST modes | $A0000-$A7FFF | 32 KB video plane in logical address space |
| LORAM (320x200x2) | Plane 0: $A0000-$A7FFF | 256 colors via palette |
| MORAM (640x200x4) | Plane 0: $A0000-$A3FFF | 4-bit per pixel |
| HIRE (640x400x1) | Plane 0: $A0000-$A3FFF | 1-bit per pixel (monochrome) |

```
+--------------------------+----------+----------+------------------+

+--------------------------+----------+----------+------------------+
| 68000 CPU Clock          | 8 MHz    | 8/14 MHz | 8/16 MHz         |

| Bus arbitration latency  | ~200 ns  | ~150 ns  | ~150 ns          |
| Blitter bus share        | N/A      | 64 cycles| 64 cycles        |
| DMA transfer rate        | 256 ns   | 256 ns   | 256 ns           |

+--------------------------+----------+----------+------------------+
```

**Key timing improvements in GST MCU:**
- DRAM refresh is more efficient: the MMU block in the GST MCU has a dedicated DRAM row counter that reduces address decode latency
- Bus arbitration latency is slightly reduced (on-chip signals vs. inter-chip signals)
- The page mapping register is software-programmable, allowing dynamic memory configuration
- New DMA capabilities (stereo sound DMA via GST Shifter, controlled by GST MCU)

## STe Bus Interface

### Bus Architecture

The GST MCU sits at the center of the 68000 system bus between the CPU and all memory/peripherals:

```
                    68000 System Bus
```

## Emulation Notes

### Existing Emulation Implementations

| Project | Type | Accuracy | GST MCU Coverage |
|---------|------|----------|-----------------|
| **AtariST_MiSTer** (Jorge Cwik / CrunC) | FPGA Verilog | Cycle-accurate | Complete GST MCU + Shifter + Blitter |
| **gyurco/gstmcu** | Verilog simulation | Gate-level | Complete GST MCU + Shifter (from reconstructed schematics) |

### AtariST_MiSTer GST MCU Implementation

The [AtariST_MiSTer](https://github.com/MiSTer-devel/AtariST_MiSTer) project by Jorge Cwik provides the reference FPGA implementation:

- **GST MCU is a top-level submodule** in the MiSTer architecture
- The GST MCU is divided into GLUE, MMU, DMA, and Blitter submodules
- The MMU page mapping is stored in on-chip RAM (32 entries, configurable at runtime)
- Scroll registers are implemented as a shift register chain (8 x 12-bit)
- DRAM refresh is a dedicated state machine with 10-bit row counter
- Blitter engine uses a pipeline architecture matching the hardware data path
- Bus arbitration between 68000 and blitter uses a 64-cycle time-slice counter
- All signals are synchronous to the CLK_8MHZ domain
- The MMU scroll registers are implemented in a separate `mmu_scroll` submodule

### gyurco/gstmcu Verilog Model

The [gyurco/gstmcu](https://github.com/gyurco/gstmcu) repository contains:

- **Gate-level Verilog** (identical to the original CMOS implementation): reconstructed from schematics recovered by Christian Zietz
- **Synchronous Verilog** model: suitable for FPGA synthesis, functionally equivalent to the gate-level circuit
- **Testbench**: runs the GST MCU+Shifter from power-on, generates RGB output (~10 seconds of video) and VCD waveforms
- Based on the C302183-002 variant (with blitter)
- The Shifter is a separate Verilog module (GST Shifter C029145)

### Key Emulation Details

1. **MMU Page Mapping** must be implemented as a 32-entry lookup table. At reset, Identity mapping is used (page N -> physical page N). TOS reprograms this to accommodate more than 4 MB or memory banking.

2. **DRAM Refresh** must be a separate state machine from the MMU page mapping. The row counter runs independently (10-bit, 0-1023) and generates RAS/CAS pulses at the correct timing. The GST MCU does NOT wait for 68000 bus cycles to refresh DRAM.

3. **Scroll registers** must be 8 separate 12-bit values, not a single 96-bit value. Each scroll digit affects a different portion of the effective memory address.

4. **Page mapping vs scrolling** interact: the GST MCU first applies page mapping (if enabled), then adds the scroll offset to the mapped address. The scroll offset is applied to page-relative addresses (i.e., the lower bits of the address).

5. **Blitter emulation** requires cycle-accurate bus access:
   - In shared mode, alternates 64 CPU cycles / 64 blitter cycles
   - In HOG mode, completely halts the 68000
   - Premature restart (clear+set BUSY within 7 cycles) must be supported for correct demo/scene software behavior
   - Register write-back reads current counter values (not initial values)

6. **GST MCU registers at $FEC000-$FEFFFF** must be decoded correctly. Writing to these addresses affects:
   - GST MCU control (reset, page map enable/disable)
   - Port A/B/C (parallel I/O)
   - Counter/timer
   - Joystick/paddle ADC
   - CRT control (super hires, pixel doubling)
   - Genlock input

7. **MAD (DRAM address) signals** are critical for DRAM simulation. They are driven by the MMU block at a fixed rate regardless of the 68000 CPU state.

8. **Mega STE vs STe**: The Mega STE has additional SH2 chip registers that control memory mapping for >4 MB configurations. The GST MCU registers are the same, but the SH2 chip adds additional address decode layers.

### Common Emulation Bugs

| Bug | Cause | Fix |
|-----|-------|-----|
| Screen is all white/black | Page mapping entry 0 = 0xFF (invalid) | Default to identity map at reset |
| Scrolling works but display is garbled | Scroll digit boundaries are wrong | Scroll digits each represent a portion of the 12-bit page-relative offset |
| Blitter reads stale data | Source buffer not drained between lines | Drain 32-bit source buffer at end of each line |
| DMA doesn't work | Bus arbitration priority wrong | DMA > CPU > Blitter in priority |
| Video sync issues | GST MCU vs Shifter domain crossing | Use proper synchronization between GST MCU control signals and Shifter |
| Sound playback at wrong speed | GST MCU timer for DAC clock wrong | Timer clock must be derived from the correct phase of the 8 MHz clock |
| STe Super Hi-Res not working | Pixel doubling not implemented | Enable pixel-doubled mode via $FEC020-$FEC02B control registers |
