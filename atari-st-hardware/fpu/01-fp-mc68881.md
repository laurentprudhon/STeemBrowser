# Atari ST FPU (MC68881 / MC68882) — Detailed Documentation

## 1. Overview: FPU in the Atari ST/STE Family

The Atari ST line of 16/32-bit computers (ST, Mega ST, Mega STE, TT030, Falcon030) used the Motorola MC68881 or MC68882 floating-point coprocessor to accelerate mathematical operations that the base MC68000/MC68030 CPU cannot perform in hardware — specifically, floating-point arithmetic, trigonometric functions, and other real-number computations.

### Which models support the FPU?

| Model | FPU Default | FPU Option | Interface Mode | Notes |
|---|---|---|---|---|
| Atari ST / ST FM / STe | Not installed | External via SFP-004 or board mods | Peripheral mode | 68000 has no native FPU interface |
| Mega ST | Not installed | SFP-004 add-on (PLCC 44-pin adapter) | Peripheral mode | 8 MHz 68000 |
| Mega STE | Socket on board (W3 jumper) | MC68881 or MC68882 in PLCC44 socket | Peripheral mode | 16 MHz 68000, internal FPU socket |
| TT030 | MC68882 @ 32 MHz (default) | Built-in | Coprocessor mode | 68030 @ 32 MHz, has native FPU interface |
| Falcon030 | Optional | PLCC44 socket (user-installable) | Coprocessor mode | 68030 @ 16 MHz, 64-pin PLCC socket |

### How the FPU is installed

**Mega STE:** The motherboard has a PLCC44 footprint for the FPU. An optional GAL/PLD chip (which decodes the F-line instruction space and routes requests) and jumper W3 enable the FPU. With W3 closed (and the GAL programmed), the FPU appears at memory addresses `$FFFA40–$FFFA60`.

**Mega ST / ST:** The Atari SFP-004 Floating-Point Coprocessor board connected to the MegaBus slot. It contains the MC68881, the necessary decoding PAL/GAL, and address-mapped registers. A later revision used a PLCC44 adapter to mount the chip directly.

**TT030 / Falcon030:** 68030-based models communicate with the FPU in true coprocessor mode via the M68020/68030 F-line bus interface — no software register polling required.

**Aftermarket / DIY:** The PAMC-500 for Amiga, ATSpeedST for Atari ST, and various PAK68 boards also provided FPU sockets. On the ST, users could add a GAL chip (e.g., an ATF16V8B) to decode F-line instructions into the `$FFFA40` mapped register set.

## 2. MC68881 Chip Pinout (20-pin PDIP/DIP)

The MC68881 was originally offered in a 20-pin package (PDIP, CDIP, or CERDIP). The pinout is:

```
                    +---------+
               NC 1 |         | 20  VSS  (GND)
        FS0   2 |         | 19  A4
        FS1   3 |         | 18  A3
         A0   4 |         | 17  A2
         A1   5 |         | 16  A1
         A2   6 |         | 15  A0
      A3 / A3  7 |         | 14  VDD (+5V)
           A4  8 |         | 13  EDS
    DS / /BSP  9 |         | 12  EAB
      AS*  10 |         | 11  DS
                    +---------+
               NC
```

| Pin # | Signal | Direction | Description |
|---|---|---|---|
| 1 | NC | — | No connect |
| 2 | FS0 | Input | Floating-point data format selector (bit 0) — with FS1 selects one of 7 data formats |
| 3 | FS1 | Input | Floating-point data format selector (bit 1) — 00=single, 01=double, 10=extended, 11=packed BCD |
| 4 | A0 | Input | Address bus bit 0 |
| 5 | A1 | Input | Address bus bit 1 |
| 6 | A2 | Input | Address bus bit 2 |
| 7 | A3 | Input | Address bus bit 3 |
| 8 | A4 | Input | Address bus bit 4 |
| 9 | DS / BSP | I/O | Data strobe / Bus status — indicates valid data on D0–D15 |
| 10 | AS* | Input | Address strobe (active low) — addresses and data bus when asserted |
| 11 | DS | Input | Data strobe (active high) — latches data on negative edge |
| 12 | EAB | Output | Enable address bus — tri-states address outputs |
| 13 | EDS | Output | Enable data strobe — controls data bus timing |
| 14 | VDD | — | +5V supply |
| 15–20 | Per pin | See above | (symmetric with pins 5–10) |

### Detailed Pin Descriptions

| Pin | Name | Description |
|---|---|---|
| 1 | NC | Internally unconnected. Must be left floating. |
| 2 | FS0 | Format select bit 0. Combined with FS1 pins. For all modes: `00` = single precision, `01` = double precision, `10` = extended precision, `11` = packed decimal. |
| 3 | FS1 | Format select bit 1. Driven by the 68000 via address decoding. |
| 4 | A0 | Address bus bit 0. Part of the 5-bit address bus for CIR port selection. |
| 5 | A1 | Address bus bit 1. |
| 6 | A2 | Address bus bit 2. |
| 7 | A3 | Address bus bit 3. |
| 8 | A4 | Address bus bit 4. |
| 9 | DS / BSP | Data status. Active during data transfer. The 68881 uses this to signal data validity. |
| 10 | AS* | Address strobe (active low). When asserted, the MCU places addresses on A0–A4. |
| 11 | DS | Data strobe (active high). When asserted, the data bus D15–D0 is valid. Latched on the falling edge. |
| 12 | EAB | Enable Address Bus. Active high — enables the address bus outputs. Pulled high externally when not in use. |
| 13 | EDS | Enable Data Strobe. Active high — enables the data strobe output. Pulled low when not used. |
| 14 | VDD | Power supply, +5V. |
| 15 | VSS | Ground. |
| 16 | A3 | Address bus bit 3 (returns on other side of DIP). |
| 17 | A2 | Address bus bit 2. |
| 18 | A1 | Address bus bit 1. |
| 19 | A0 | Address bus bit 0. |
| 20 | VSS | Ground. |

### Address Decode for CIR (Coprocessor Interface Registers)

In the Atari ST peripheral-mode mapping, the 5 address bits A0–A4 (from the 68000) are decoded along with chip-select logic (A-line/F-line decode and FC0–FC2):

```
Address Mapping ($FFFAxx region):
+-----------+-------------------------------+
| Address   | Register                      |
+-----------+-------------------------------+
| $FFFA40   | FPCIR  (FP Coprocessor Interface Reg) |
| $FFFA42   | FPCTL  (FP Control)                   |
| $FFFA44   | FPSAV  (FP Save)                    |
| $FFFA46   | FPREST (FP Restore)                 |
| $FFFA48   | FPOPR  (FP Operation)               |
| $FFFA4A   | FPCMD  (FP Command)                 |
| $FFFA4C   | FPRES  (Reserved)                   |
| $FFFA4E   | FPCCR  (FP Condition Code Reg)     |
| $FFFA50   | FPOP   (FP Operand — 32-bit)      |
+-----------+-------------------------------+
| $FFFA58   | (FPOP upper, extended)           |
+-----------+-------------------------------+
```

## 4. Floating-Point Instruction Set

### 4.1 Data Types Supported

The MC68881 supports 7 data formats:

| Format | Bits | Exponent | Mantissa | IEEE 754 Conformant |
|---|---|---|---|---|
| Single-precision real | 32 | 8 (bias 127) | 23 | Yes |
| Double-precision real | 64 | 11 (bias 1023) | 52 | Yes |
| Extended-precision real | 96* | 15 (bias 16383) | 64 | Yes* |
| 8-bit integer | 8 | — | — (two's complement) | No |
| 16-bit integer | 16 | — | — (two's complement) | No |
| 32-bit integer | 32 | — | — (two's complement) | No |
| Packed BCD | 64 | — | — (BCD digit pairs) | No |

*The 68881 uses a non-standard 96-bit extended format internally (64-bit mantissa + 15-bit exponent + 1 sign bit), whereas IEEE 754 double-extended uses 80-bit (64-bit mantissa + 11-bit exponent + 1 sign).

### 4.2 Instruction Categories

```
+=================================================================+

|----------------+-------------------------------------------------+

|                | register move                                     |

|                | FSUB <src>,<dest>   — Floating-point subtract    |
```

### 4.3 FMOVE Instruction Encoding

```
FMOVE <ea>,<Rn> — Source Effective Address to Destination Register
FMOVE <Ra>,<ea> — Source Register to Destination Effective Address

Binary encoding of FMOVE (16-bit word in F-line opcode):
  1111 1ddd ssss sss0 0RRR
    |    |     |     |    +-- Destination Register (000-111 = FP0-7)
    |    |     |     +------ Reserved (must be 0)
    |    |     +------------ Source Register (000-117 source)
    |    +------------------ Destination format specifier:
    |                       101 = double precision real (64-bit)
    |                       100 = single precision real (32-bit)
    |                       110 = extended precision real (80-bit)
    |                       101 = packed decimal (64-bit)
    +----------------------- Opcode = $F400 (R->ea) or $F500 (ea->R) etc.
```

### 4.4 Condition Codes

The 68881 sets condition codes C (carry), V (overflow), and N (negative) in the CPU's SR after FP comparison operations:

| Condition | Meaning |
|---|---|
| C set | Compare result was unordered (NaN) |
| C clear, V set | Result was equal |
| C clear, V clear | Result was orderable (less, greater, or unordered) |
| N set | Previous operation produced negative result |
| V set | Overflow occurred in arithmetic |

## 5. 68000 CPU Interface

### 5.1 Peripheral Mode (Mega ST / Mega STE / Atari ST)

The MC68000 has **no native coprocessor interface**. Instead, the 68881 is mapped as a **memory-mapped peripheral** at `$FFFA40–$FFFA60`. The 68000 must use special F-line trap instructions (decoded by external logic) to communicate.

```
68000 CPU                          68881 FPU
+-----------+                      +-----------+
|           |  AS* (Address Strobe) |         |
|           |<--------------------- | A0-A4    |
| Bus       |  A0-A4 (Address bus) |         |
| Controller|<--------------------- |         |
|           |  D0-D15 (data bus)  --->|       |
|           |---------------------->| Data Strobe |
|           |  <-------------------- | DS         |
|           |  DTACK (acknowledge) |         |
|           |<--------------------- |         |
+-----------+                      +-----------+

Protocol:
1. 68000 decodes F-line instructions as traps ($Fnnn).
2. External GAL decodes trap number to a register address ($FFFA40+).
3. CPU writes to FPCMD (command) or FPOP (operand).
4. 68881 processes and asserts DTACK to acknowledge.
5. CPU reads result from FPCIR or FPOP.
```

### 5.2 Coprocessor Mode (TT030 / Falcon030)

In 68030-based systems, the 68881/68882 is interfaced in **true coprocessor mode**:

```
68030 CPU                          FPU
+-----------+                      +-----------+
|           |  F-line (F0-F3) bus |         |
|           |<-------------------- |           |
| Bus Unit  |  A0-A4, D0-D15      --->|       |
|           |   (coprocessor bus) |         |
|           |  <------------------- |           |
|           |  DTACK, wait states  |         |
|           |<-------------------- |           |
+-----------+                      +-----------+
```

Key differences:

| Feature | Peripheral Mode (68000) | Coprocessor Mode (68020/68030) |
|---|---|---|
| Interface | Memory-mapped registers | Direct bus protocol |
| Instruction encoding | $F000–$FFFF opcodes | $Fnnn F-line instructions |
| Communication | Software polling of FPCIR | Hardware handshake |
| Pipeline | None (stalls until DTACK) | Full pipeline support |
| Address mode | CPU computes EA, sends to FPOP | CPU passes EA to FPU directly |
| Exception vectors | Via GAL + trap handler | Dedicated FPU exception vectors |
| Programming complexity | High (manual register protocol) | Transparent to programmer |

### 5.3 Bus Cycle Timing

```
68881 Bus Cycle (Peripheral Mode):
+----------------------------------------------------------+
| Phase     | Bus Activity                                    |
|-----------+------------------------------------------------|
| S0-S3     | 68000 places address on bus + assert AS*         |
| S4        | 68881 decodes address, asserts DTACK* (acknowledge)|
| S5-S6     | Data transfer on D0-D15 (1 word, 16 bits)       |
| S7          | AS* de-asserted, bus cycle complete               |
|-----------+------------------------------------------------|
| Total:    | 1 wait state typically, FPU processing time     |
|             | is handled asynchronously                       |
+----------------------------------------------------------+

Response codes returned by FPCIR after writes:
+-----------+--------------------------------------------------+
| Response | Meaning                                              |
+-----------+--------------------------------------------------+
| $0400    | Null — FPU is idle, ready for next command             |
| $0802    | Idle — Command complete                                |
| $1600    | Transfer Data (CPU to FPU) — write to FPOP             |
| $1608    | Transfer Data (CPU to FPU) — 8 bytes to FPOP           |
| $3200    | Transfer Data (FPU to CPU) — read from FPOP            |
| $3208    | Transfer Data (FPU to CPU) — 8 bytes from FPOP         |
| $8900    | Come Again — FPU needs another access                  |
| $B10X    | Execute — FPU instruction is being processed            |
+-----------+--------------------------------------------------+
```

### 6.2 Clock Connection

```
Clock System:
+-------------------------------------------------------------+
|                                                             |
|  8 MHz (ST/FM) / 16 MHz (STE)                             |
|      |                                                      |
|      +-----> 68000 CLK (8/16 MHz)                         |
|      |                                                      |
|      +-----> FPU CLK (via clock buffer)                    |
|                 |                                            |
|                 v                                            |
|           MC68881 @ same clock rate                          |
|           (e.g., MC68881P16 at 16 MHz for STE)             |
|                                                             |
|  Note: MC68881/882 has an internal PLL for the ECU clock   |
|  and separate clock domains for memory interface.           |

```

- **Mega ST:** 8 MHz external clock. FPU runs at 8 MHz (e.g., MC68881P12 or MC68881P16).
- **Mega STE:** 16 MHz external clock. FPU typically runs at 16 MHz.
- **TT030:** 32 MHz CPU, 16 MHz system bus. MC68882 runs at 32 MHz.
- **Falcon030:** 16 MHz 68030. Optional 68881/68882 at 16 MHz max.

### 6.3 Enable Logic (Mega STE)

```
FPU Enable Logic (Mega STE schematic simplified):

  68000 address bus (A0-A19)
        |
        v
  [Lattice GAL / PLD]   <-- ATF16V8B programming:
        |                 decode $FFFA40 region + F-line trap $F000-F3FF
        |
        +-----> FPU CS (chip select)
        +-----> AS* to FPU
        +-----> DTACK* to 68000
        +-----> Data buffer control
        |
        [Jumper W3]  <-- Physical jumper:
        open = FPU disabled
        closed = FPU enabled

  Jumper W3 on Mega STE motherboard:
  - Open: FPU disabled (default on boards without FPU)
  - Closed: FPU enabled (for boards with FPU socket populated)

  Note: Some Mega STE boards have R37 (resistor) cut to enable FPU.
```

### 6.4 Atari ST (non-STE) Integration

On the original ST (ST FM/STM), the 68000 does not support coprocessor mode. FPU support is added via:

1. **External board** (PAMC, PAK68, SFP-004 clone) plugged into expansion
2. **GAL chip** that intercepts F-line trap opcodes ($F400-$F5FF for FMOVE, etc.)
3. **Address decode** maps the trap destination to `$FFFA40+` register window
4. **A-line decode** uses address bit A23 to select FPU register space

```
Atari ST F-line decode logic:

  68000 executes: FMOVE #val, FP0  = $F504xxxx
        |
        +----> GAL decodes $F4xx-$F5xx opcode range
        +----> GAL maps to $FFFA40-$FFFA60 register window
        +----> CPU writes to $FFFA4A (FPCMD)
        +----> 68881 receives command via data bus
        +----> DTACK* returned when ready
```

### 7.3 TT030 Performance (MC68882 @ 32 MHz)

The TT030 with built-in 68882 achieved significantly better performance:
- ~5x faster FP throughput than Mega STE with SFP-004
- Near-native FP performance due to 68030 coprocessor bus
- No software register-polling overhead

### 8.3 FSAVE/FRESTORE State Frame

```
FSAVE State Frame (80881 format, 240 bytes):

  Offset  Size  Field                    Description
  ------  ----  -----------------------  -----------------------------
  0x00      2   FPCR (low 16 bits)      Control register low word
  0x02      2   FPCR                     Control register high word
  0x04      2   FPSR (low 16 bits)      Status register low word
  0x06      2   FPSR                     Status register high word
  0x08      10  FP0: 80-bit format       Floating-point register 0
  0x12      10  FP1                     Floating-point register 1
  0x1C      10  FP2                     Floating-point register 2
  0x26      10  FP3                     Floating-point register 3
  0x30      10  FP4                     Floating-point register 4
  0x3A      10  FP5                     Floating-point register 5
  0x44      10  FP6                     Floating-point register 6
  0x4E      10  FP7                     Floating-point register 7
  0x58     ...   (alignment bytes)       Padding to 240 bytes total
```

### 8.4 Common Emulation Pitfalls

1. **Response code timing:** The 68881 must return a valid primitive response code *after every* access to FPCMD or FPOP. The sequence `$1600` (CPU-to-FPU data) followed by `$8900` (come again) is required for multi-word transfers.

2. **FSAVE frame size mismatch:** The MC68882 uses a 248-byte frame (adds FPIAR = 32-bit address register), while the 68881 uses 240 bytes. Emulators must distinguish between the two.

3. **Non-standard extended format:** The 68881's internal 96-bit extended format (64-bit mantissa) differs from IEEE 754 double-extended (80-bit mantissa). Emulators must use the 68881's format for correct results.

4. **Condition code propagation:** The 68881 sets the 68000's SR condition codes (C, V, N, Z) after FP compare instructions. These must be reflected in the emulated CPU state.

5. **Rounding modes:** FPCR controls rounding (nearest, down, up, truncation). Emulators must respect this setting.

6. **Precision control:** FPCR bit 2-3 controls output precision (single, double, extended). Results must be rounded to the specified precision.

7. **FPU presence detection:** Atari TOS calls `$0001B8` (`CnOpSn`) or uses `CnOp(0, 1)` to check FPU presence. Emulators must make this succeed when FPU is enabled.
