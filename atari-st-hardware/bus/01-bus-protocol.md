# Bus Protocol

> Detailed description of the 68000 bus cycles on the Atari ST and how peripherals interact with the CPU through the bus system.

## Overview

The Atari ST bus uses the Motorola 68000 synchronous bus protocol at **8 MHz** (16 MHz on Mega STE). Each bus cycle takes **4 phase times** (125 ns each at 8 MHz = 500 ns total).

## Bus Cycle Types

### Read Cycle (4 phase times)
```
Phase 1 (t0-t7):  Address placed on A0-A23
Phase 2 (t8-t15): AS goes low, FC0-FC2 placed
Phase 3 (t16-t23): UDS/LDS strobe, data bus floating
Phase 4 (t24-t31): Data valid on D0-D15
```

### Write Cycle
```
Phase 1 (t0-t7):  Address placed on A0-A23
Phase 2 (t8-t15): AS goes low, FC0-FC2 placed
Phase 3 (t16-t23): D0-D15 placed, R_W=0 (Write)
Phase 4 (t24-t31): AS strobes, data latched
```

### DMA Cycle
```
Phase 1 (t0-t7):  DMA chip generates address (only A1 used)
Phase 2 (t8-t15): AS=high (DMA cycle)
Phase 3 (t16-t23): D0-D15 accessed, R_W determines direction
Phase 4 (t24-t31): DTACK from DMA chip completes cycle
```

### First-word Cycle (DMA special)
Special cycle for DMA that writes the first word of a data buffer:
1. CPU starts DMA cycle with $FF8A00 address
2. DMA chip takes over at phase 2
3. DMA reads first word from $FF8A02 (or $FF8A00 depending on config)
4. DMA generates its own DTACK
5. DMA controls the bus for subsequent data transfers

## Bus Timing Details

### Address Phase
- Address placed at t0 (phase 1 start)
- AS (Address Strobe) goes low at t8 (phase 2 start)
- FC0-FC2 valid at phase 2 start
- Address remains valid until next cycle

### Data Phase
- UDS (upper data strobe) goes low at t16
- LDS (lower data strobe) goes low at t16
- R/W (read/write) valid at phase 2
- Data valid on D0-D15 at t24
- Data valid until t32 (DTACK must arrive by t32)

### DTACK Timing
- External DTACK: peripheral responds within 1 phase time
- Glue DTACK: generated by Glue chip for standard I/O regions
- DMA DTACK: generated by DMA chip during DMA transfers

### DRQ / DMA Handshake
```
DMA peripheral --> FDRQ (active low) to DMA chip
DMA chip --> BG (active low) to 68000
68000 --> BGACK (active low) to DMA chip
DMA chip --> !ACK to DMA peripheral
Data transfer occurs on D0-D15
DMA chip de-asserts BR and BG
68000 resumes bus control
```

### Function Code Decoding

The FC0-FC2 lines determine which regions are accessible:

| FC2 | FC1 | FC0 | Bus Cycle Type | Regions |
|-----|- --|--|- |-|
| 0 | 0 | 0 | User program fetch | ROM only |
| 0 | 0 | 1 | User data | RAM, ROM |
| 0 | 1 | 0 | User data (I/O access) | All |
| 0 | 1 | 1 | User data (I/O access) | All |
| 1 | 0 | 0 | Supr program fetch | ROM only |
| 1 | 0 | 1 | Supr data | All |
| 1 | 1 | 0 | Supr data (I/O) | All |
| 1 | 1 | 1 | Supr data (I/O) | All |

### User Mode Address Restrictions

In user mode (S=0):
- Addresses $000000-$0007FF (first 2 KB) are inaccessible
- Any access to these generates a **bus error** (exception 2)

## DMA Bus Arbitration

### Cycle interleaving

The ST bus uses **cycle interleaving**:
- CPU and DMA share the same bus
- In each bus cycle, either the CPU or DMA controls the bus
- DMA requests can occur during any CPU bus cycle
- DMA has highest priority over FDC

### DMA timing
- DMA read/write cycles take 2 bus cycles minimum
- First-word DMA read takes an extra cycle
- Each DMA cycle is 500 ns (8 MHz) at 8 MHz
- The CPU can still access internal registers while DMA holds the external bus

## DRAM Refresh Timing

The DRAM refresh is handled autonomously:
- Refresh occurs during CPU read cycles (the MMU converts CPU reads to DRAM refresh cycles)
- Each DRAM row needs refresh every 4 ms (standard DRAM timing)
- With ~4096 rows, refresh cycles are spaced at ~1 ms intervals
- The Glue chip schedules refresh cycles automatically
