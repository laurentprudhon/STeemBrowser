# WD1772 FDC Implementation - Steem SSE

## Overview

The WD1772 (Western Digital FD1772) is a Floppy Disk Controller (FDC) chip used in the Atari ST to control the floppy disk drives. It handles all aspects of floppy disk operation, including reading, writing, formatting, and seeking.

This document describes how the WD1772 FDC is emulated in Steem SSE, including its architecture, command processing, disk image handling, and integration with the DMA system.

## Hardware Background

### FDC Chip Functions

The WD1772 FDC performs several critical functions in the Atari ST:

1. **Disk I/O**: Reads and writes data from/to floppy disks
2. **Command Processing**: Executes a variety of floppy disk commands
3. **Data Encoding/Decoding**: Handles MFM (Modified Frequency Modulation) encoding
4. **Seek Control**: Moves the disk head to specified tracks
5. **Interrupt Generation**: Signals the CPU when operations complete
6. **DMA Integration**: Works with the DMA chip for data transfers

### Key Specifications
- **Package**: PDIP40 (40-pin Plastic Dual In-line Package)
- **Data Rate**: 250-500 kbps (depending on disk type)
- **Commands**: 44 different commands for disk operations
- **Data Encoding**: MFM (Modified Frequency Modulation)
- **Track Capacity**: Up to 11 sectors per track (720KB disks)
- **Sector Sizes**: 128, 256, 512, or 1024 bytes per sector

### Command Types

The WD1772 supports four types of commands:

1. **Type I**: Immediate commands (execute immediately)
2. **Type II**: Commands that read data from disk
3. **Type III**: Commands that write data to disk
4. **Type IV**: Special commands (e.g., read address)

### Register Map

The FDC registers are memory-mapped at addresses 0xFF8604-0xFF8607:

```
FDC REGISTER MAP:
┌─────────────────────────────────────────────────────────────┐
│ Address   │ Register Name          │ R/W  │ Description      │
├───────────┼────────────────────────┼──────┼──────────────────┤
│ 0xFF8604  │ Status Register        │ R    │ FDC status        │
│ 0xFF8604  │ Command Register       │ W    │ FDC command       │
│ 0xFF8605  │ Track Register         │ R/W  │ Current track     │
│ 0xFF8606  │ Sector Register        │ R/W  │ Current sector    │
│ 0xFF8607  │ Data Register          │ R/W  │ Data transfer     │
└─────────────────────────────────────────────────────────────┘

Note: The Status and Command registers share the same address (0xFF8604).
Reading from this address returns the status, writing to it sends a command.
```

## Core Functionality

### 1. Register Access

The FDC registers are accessed through memory-mapped I/O:

```cpp
// In fdc.cpp
BYTE fdc_read_byte(MEM_ADDRESS ad) {
    // Handle FDC register reads
    if (ad == 0xFF8604) {
        // Status register
        return Fdc.str;
    } else if (ad == 0xFF8605) {
        // Track register
        return Fdc.tr;
    } else if (ad == 0xFF8606) {
        // Sector register
        return Fdc.sr;
    } else if (ad == 0xFF8607) {
        // Data register
        return Fdc.dr;
    }
    return 0xFF; // Invalid address
}

void fdc_write_byte(MEM_ADDRESS ad, BYTE value) {
    // Handle FDC register writes
    if (ad == 0xFF8604) {
        // Command register
        Fdc.NewCommand(value);
    } else if (ad == 0xFF8605) {
        // Track register
        Fdc.tr = value;
    } else if (ad == 0xFF8606) {
        // Sector register
        Fdc.sr = value;
    } else if (ad == 0xFF8607) {
        // Data register
        Fdc.dr = value;
        Fdc.WriteCR(value);
    }
}
```

### 2. Command Processing

The FDC processes commands through a state machine:

```cpp
void TWD1772::NewCommand(BYTE command) {
    // Start a new command
    
    // Store the command
    cr = command;
    old_cr = command;
    
    // Reset status
    str = 0;
    
    // Determine command type
    BYTE type = CommandType(command);
    
    // Set up initial state based on command type
    switch (type) {
        case 1: // Type I - Immediate commands
            prg_phase = WD_TYPEI_SPINUP;
            break;
        case 2: // Type II - Read commands
            prg_phase = WD_TYPEII_SPINUP;
            break;
        case 3: // Type III - Write commands
            prg_phase = WD_TYPEIII_SPINUP;
            break;
        case 4: // Type IV - Special commands
            if (command == 0xD0) {
                prg_phase = WD_TYPEIV_4;
            } else if (command == 0xD8) {
                prg_phase = WD_TYPEIV_8;
            }
            break;
    }
    
    // Start command execution
    fdc_execute();
}

void fdc_execute() {
    // Execute the current FDC command
    // This is called repeatedly until the command completes
    
    // Process current phase
    switch (Fdc.prg_phase) {
        case WD_TYPEI_SPINUP:
            TypeI_Spinup();
            break;
        case WD_TYPEI_SPUNUP:
            TypeI_Spunup();
            break;
        case WD_TYPEI_SEEK:
            TypeI_Seek();
            break;
        // ... many more cases ...
        case WD_MOTOR_OFF:
            MotorOff();
            break;
    }
}
```

### 3. Command Types

#### Type I Commands (Immediate)

Type I commands execute immediately and don't involve data transfer:

```cpp
void TWD1772::TypeI_Spinup() {
    // Spin up the motor
    Motor(true);
    
    // Set timeout for spin-up
    update_time = A_S_T + Fdc.MsToCycles(200); // 200ms spin-up time
    
    // Move to next phase
    prg_phase = WD_TYPEI_SPUNUP;
}

void TWD1772::TypeI_Spunup() {
    // Motor is spun up, check if we need to seek
    if (cr & CR_SEEK) {
        prg_phase = WD_TYPEI_SEEK;
    } else if (cr & CR_RESTORE) {
        prg_phase = WD_TYPEI_STEP_UPDATE;
    } else {
        // Command complete
        prg_phase = WD_READY;
        Irq(true); // Signal interrupt
    }
}
```

#### Type II Commands (Read)

Type II commands read data from the disk:

```cpp
void TWD1772::TypeII_Spunup() {
    // Motor is spun up, head settle time
    update_time = A_S_T + Fdc.MsToCycles(15); // 15ms head settle
    prg_phase = WD_TYPEII_HEAD_SETTLE;
}

void TWD1772::TypeII_HeadSettle() {
    // Head has settled, find ID
    prg_phase = WD_TYPEII_FIND_ID;
    
    // Start looking for ID field
    OnIndexPulse(0);
}

void TWD1772::TypeII_FindID() {
    // Look for ID field
    // This involves scanning the track for the ID address mark
    
    if (FindIDField()) {
        prg_phase = WD_TYPEII_READ_ID;
    } else {
        // Keep looking
        update_time = A_S_T + Fdc.MsToCycles(1);
    }
}

void TWD1772::TypeII_ReadID() {
    // Read ID field
    ReadIDField();
    
    prg_phase = WD_TYPEII_TEST_ID;
}

void TWD1772::TypeII_TestID() {
    // Test if ID matches what we're looking for
    if (TestIDField()) {
        prg_phase = WD_TYPEII_FIND_DAM;
    } else {
        prg_phase = WD_TYPEII_FIND_ID;
    }
}

void TWD1772::TypeII_FindDAM() {
    // Look for Data Address Mark
    if (FindDAM()) {
        prg_phase = WD_TYPEII_READ_DATA;
        ByteCount = 0;
    } else {
        update_time = A_S_T + Fdc.MsToCycles(1);
    }
}

void TWD1772::TypeII_ReadData() {
    // Read data from disk
    BYTE data = ReadDataByte();
    
    // Store data in data register
    dr = data;
    
    // Signal DRQ (Data Request)
    Drq(true);
    
    // Check for end of sector
    ByteCount++;
    if (ByteCount >= IDField.nBytes()) {
        prg_phase = WD_TYPEII_READ_CRC;
    }
}
```

void TWD1772::TypeIII_IP_START() {

    WaitIP = true;
    WaitImage = true;
    
    // Set up for write
    prg_phase = WD_TYPEIII_WRITE_DATA;
}

void TWD1772::TypeIII_WriteData() {
    // Write data to disk
    if (WaitIP) {
        // Wait for index pulse
        if (floppy_track_index_pulse_active()) {
            WaitIP = false;
        }
    } else {
        // Write data byte
        WriteDataByte(dr);
        
        // Signal DRQ for next byte
        Drq(true);
        
        // Check for end of sector
        ByteCount++;
        if (ByteCount >= IDField.nBytes()) {
            prg_phase = WD_TYPEIII_WRITE_CRC;
        }
    }
}

### 5. MFM Encoding/Decoding

The FDC handles MFM (Modified Frequency Modulation) encoding for disk data:

```cpp
// In fdc.cpp
void TWD1772MFM::Decode() {
    // Decode MFM data
    // Convert from encoded format to raw data
    
    // Extract clock and data bits
    clock = (encoded >> 8) & 0xFF;
    data = encoded & 0xFF;
    
    // Decode using MFM rules
    // MFM: Clock bits are suppressed if they would be between two 1s
    // This is a simplified version - real MFM decoding is more complex
    
    data_last_bit = (data & 1) != 0;
}

void TWD1772MFM::Encode(int mode) {
    // Encode data using MFM
    // mode: NORMAL_CLOCK or FORMAT_CLOCK
    
    // Encode data and clock bits
    // This involves inserting clock bits according to MFM rules
    
    encoded = (clock << 8) | data;
}
```

### 6. CRC Calculation

The FDC calculates and checks CRC (Cyclic Redundancy Check) for data integrity:

```cpp
// In fdc.cpp
void fdc_add_to_crc(WORD &crc, BYTE data) {
    // Add byte to CRC calculation
    // WD1772 uses CRC-16 with polynomial x^16 + x^12 + x^5 + 1
    
    crc ^= (data << 8);
    
    for (int i = 0; i < 8; i++) {
        if (crc & 0x8000) {
            crc = (crc << 1) ^ 0x1021;
        } else {
            crc <<= 1;
        }
    }
}

void fdc_make_crc16_table() {
    // Precompute CRC table for faster calculation
    for (int i = 0; i < 256; i++) {
        WORD crc = i << 8;
        for (int j = 0; j < 8; j++) {
            if (crc & 0x8000) {
                crc = (crc << 1) ^ 0x1021;
            } else {
                crc <<= 1;
            }
        }
        crc16_table[i] = crc;
    }
}
```

// In fdc.cpp
void TWD1772::Drq(bool state) {
    // Data Request from FDC
    Lines.drq = state;
    
    if (state) {
        // FDC is requesting data transfer
        Dma.Drq(0); // Manager 0 = FDC
    } else {
        // Data transfer complete
        Dma.Drq(1); // Clear DRQ
    }
}

void TWD1772::OnUpdate() {
    // During FDC operations, data may need to be transferred via DMA
    if (Lines.drq && (Dma.mcr & TDma::CR_DRQ_FDC_OR_HDC) == 0) {
        // FDC DRQ is active and DMA is configured for FDC
        Dma.RequestTransfer(0, 0);
    }
}

## Conclusion

The WD1772 FDC emulation in Steem SSE is a **highly functional implementation** that accurately reproduces the behavior of the real Western Digital FD1772 Floppy Disk Controller chip. The implementation:

- **Processes all FDC commands** (Type I, II, III, IV)
- **Handles disk I/O** with proper timing and data transfer
- **Integrates with DMA** for efficient data transfers
- **Supports multiple disk image formats** (ST, MSA, STW, HFE, SCP)
- **Implements MFM encoding/decoding** for disk data
- **Calculates CRC** for data integrity checking
- **Generates accurate interrupts** for the CPU

The FDC emulation provides the **disk I/O backbone** for the Atari ST, allowing it to read and write floppy disks with high accuracy. While the FDC emulation is highly functional, some timing details and edge cases may not be perfectly reproduced compared to the real hardware.

Steem SSE offers both a standard FDC emulation and an optional low-level emulation (SSE_WD1772_LL) that provides even higher accuracy at the cost of increased resource usage.
